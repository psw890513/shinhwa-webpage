# 개발 점검 (네 칸 틀)

기능을 만들기 전과 배포 전에 아래 네 칸을 채운다. 목표는 모르는 칸의 항목을 아는 칸으로 옮기는 것이다.

## 1. Known Knowns (알고 있다는 걸 아는 것)
확실히 정해진 사항이다.
- `CLAUDE.md`와 기존 코드에서 확인한 요구사항, 구조, 규칙을 적는다.
- 대응: 문서에 적힌 대로 진행한다. 바뀌면 `CLAUDE.md`를 갱신한다.

## 2. Known Unknowns (모른다는 걸 아는 것)
정해야 하지만 아직 정하지 못한 것이다.
- 이 프로젝트의 예: 실제 전화번호, 주소, 사업자번호, 임대료, 장비 사진, 도메인, Firebase 계정 연결.
- 대응: 할 일 목록에 올린다. 값을 지어내지 않고 placeholder나 "견적 문의"로 둔다. 사용자에게 무엇이 필요한지 묻는다.

## 3. Unknown Knowns (알지만 꺼내지 않은 것)
사용자나 현장은 당연히 알지만 말하지 않은 것이다.
- 예: 손님이 많이 찾는 규격, 운반비 기준, 성수기, 자주 받는 질문, 업계 용어.
- 대응: 구체적인 질문으로 끄집어낸다. 예: "전화로 손님이 가장 많이 묻는 게 뭔가요?", "이 기능을 지금은 어떻게 처리하고 계세요?"

## 4. Unknown Unknowns (모른다는 것조차 모르는 것)
예상하지 못한 문제다.
- 예: 사용자가 예상과 다르게 쓰는 방식, 스팸 접수, 특정 휴대폰에서 화면이 깨짐, 검색 노출 문제.
- 대응: 작게 만들어 빨리 배포하고 확인한다. 모바일과 PC에서 직접 열어 보고, 접수 내역과 오류를 살핀다. 되돌릴 수 있게 커밋을 작게 나눈다.

## 진행 방법
1. 요청을 받으면 네 칸을 짧게 채워 사용자에게 보여 준다. 칸마다 1~4줄이면 충분하다.
2. Known Unknowns와 Unknown Knowns 중 작업을 막는 항목은 먼저 묻는다. 막지 않는 항목은 placeholder로 두고 진행한다.
3. 배포 전에는 4번 칸을 다시 보고 확인한 것(화면 폭별 확인, 폼 전송, 링크)을 적는다.
4. 결과는 한국어로, 쉬운 말로 쓴다.
